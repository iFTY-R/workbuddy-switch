# 批量操作冒烟清单

批量同步 / 批量删除只在 WorkBuddy 会话页开放。单测覆盖不到「真实客户端 + 多账号 + 关闭重开」
这一段，发版前按下面六步各走一遍，记录结果。

准备：2 个已保存账号（A 作源、B 作目标）、至少 3 个关联组，其中 1 个组的目标副本落后（状态「待同步」）。

## 1. 无授权时不关客户端

1. 保持 WorkBuddy 运行，且**当前登录账号就是某个待同步组的目标账号**；
2. 勾选该组 + 另一个普通组 → 批量同步；
3. 不勾选「允许关闭并重开 WorkBuddy」→ 开始。

预期：弹窗立刻返回结果；「正在使用」的那组显示**已跳过**，原因写「目标账号正在 WorkBuddy 中使用」；
另一组正常完成；客户端全程没有被关闭。

## 2. 授权关闭后整批一次进出

同上一组选中，勾选「允许关闭并重开」→ 开始。

预期：客户端先关闭一次（**只关一次**，不是每组一次）→ 逐组推进 → 结束后自动重开；
结果页底部出现「本次关闭过 …：已自动重开」。

## 3. 中途停止

选 4 个以上组，开始后马上点「停止后续组」。

预期：正在写的那一组照常完成；其余显示**未执行**；提示「已按请求停止」；列表状态刷新。

## 4. 中断可见

再起一批（3 个组以上），在进度跑到第 2 组时强杀进程（任务管理器 / `taskkill /F`），然后重新打开应用。

预期：列表顶部出现「上次批量（… 完成 / … 失败 / … 未执行）没有全部完成」提示；
点「查看结果」能看到 `interrupted` 说明「进程退出时还没跑完」，且未执行项可重试。

## 5. 批量删除只解关联

勾选 2 个组 → 批量删除关联 → 确认。

预期：确认框逐条列出组名；执行后这两个组从列表消失；**两个账号里的会话内容仍在**
（到客户端里确认会话还在）。

## 6. 导出报告

在任一次结果页点「导出报告」。

预期：桌面端点开保存对话框，保存后用 Excel 打开中文列名不乱码；webui 直接下载 CSV。

## 7. 覆盖中断自愈（`vscode_session_sync`）

针对 VS Code 插件侧的「覆盖已有会话」：在目标目录被退役、新目录尚未就位的瞬间中断。

预期：下次进入会话列表时该会话**不再显示「内容缺失」**；覆盖可以正常重试成功；
`~/.wb-switch/` 下不再残留 `.old-<cid>-overwrite` 目录。

## 8. 批量补副本（Phase 2）

准备：至少 2 个关联组，其中 1 个组有「可确认的安全来源」，另选 1 个**不是任何组成员**的账号作目标。

1. 勾选这两个组 → 「补副本」；
2. **不勾选任何账号**，确认「开始补副本」是禁用的（不选 ≠ 全选）；
3. 勾选目标账号 → 开始。

预期：
- 计划页给出「最多会新建 N 份副本（组数 × 账号数）」；实际数量按每组兼容账号算，可能更少；
- 执行后每个成功组显示「新建 N 份副本」，目标账号里能打开该会话且**内容是来源那一版**；
- 已经是组成员的账号不会重复复制（重跑一次应显示「所选账号都已有这个会话的副本」）；
- 副本的「上下文用量」非 0，且文件备份/工具输出与来源一致（详情页「上下文」面板可核对）；
- 副本的费用记录为空（`credit_json` 不继承）。
